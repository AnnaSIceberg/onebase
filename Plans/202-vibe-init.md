[Issue #1636](https://github.com/ivanarama/onebase/issues/1636), вариант 2,
решение `ivanarama` (5784439363): короткий план для Claude Code, Cursor,
OpenCode/ZCode. [#1634](https://github.com/ivanarama/onebase/issues/1634) независима,
без `hold`. Проверено на `main` `383d25d5`: `install.ps1` проверяет SHA-256 и
staging-бинарь, но финальное копирование не атомарно; `install.sh` отсутствует;

перезаписывает `AGENTS.md`; `internal/cli/mcp.go` уже предоставляет read-only MCP.
Регистрации клиентов нет.

## Синтаксис / YAML

`onebase vibe-init <dir> [--agents=claude,cursor,opencode,zcode] [--dry-run]`:
создать пустой проект, обнаружить клиентов по известным binary/каталогам,
добавить `onebase` в **проектные** конфиги. Явный список работает без клиента;
найденные агенты не запускать/устанавливать. Валидный существующий проект
подключать без повторного `init`; непустой чужой каталог отклонять.
Пользовательские guides сохранять. Dry-run ничего не пишет/скачивает.

| Клиент / источник формата | Файл и секция |
|---|---|
| [Claude Code](https://code.claude.com/docs/en/mcp#project-scope) | `.mcp.json`: `mcpServers.onebase`, `type: stdio`, `command` + `args` |
| [Cursor](https://cursor.com/docs/mcp) | `.cursor/mcp.json`: `mcpServers.onebase`, `command` + `args` |
| [OpenCode](https://opencode.ai/docs/mcp-servers/) | `opencode.json` / существующий `.jsonc`: `mcp.onebase`, `type: local`, `command: [binary, mcp, --project, dir]` |
| [ZCode](https://www.zcode.network/en/docs/mcp-services/) | `.zcode/config.json`: `mcp.servers.onebase`, `command` + `args` |

Пути абсолютные, аргументы массивом, без shell/write-флагов. ZCode — отдельный
адаптер. Два конфига OpenCode одновременно — отказ, выбор вручную. Перед поставкой
подтвердить форматы smoke-проверкой клиентов; неизвестный формат — отчёт и ручной блок.

## Инварианты, хранилище / SQL, совместимость

DDL/миграций нет; обычные `init`/`mcp` сохраняют контракт. Add-only вставка по токенам
JSON/JSONC сохраняет неизвестные ключи, комментарии и байты вне вставки. Совпадение —
no-op, другое значение `onebase` — конфликт. Невалидный UTF-8, duplicate keys,
неверный тип секции и symlink — отказ. Существующий файл: приватный create-only
бэкап исходных байтов с проверкой копии, временный файл рядом, валидация, sync,
атомарная замена ОС; Windows без delete-then-rename. Новый файл — create-only.
Лок сериализует наши запуски, повторное чтение обнаруживает внешнюю правку;
редактор закрыть: универсального CAS чужих writer нет. Атомарность по файлу,
при ошибке остановить следующие записи; автоматического общего отката нет.
Отчёт: клиент/путь, `added/already-present/conflict/skipped/error`, бэкап и
действие пользователя; конфликт/ошибка дают ненулевой exit.

## Verification, риски, откат и завершение

Чистый профиль, путь с пробелами/кириллицей: bootstrap, открыть проект каждым
клиентом, подтвердить штатное доверие MCP, выполнить `check`/`describe`;
повторный запуск байтово неизменен, чужие серверы работают, write-tools скрыты.
Риски форматов, Windows replace и редактора покрываются fixtures/smoke/бэкапом.
Откат вручную после сверки текущего файла: бэкап либо удаление добавленной записи;
проект/binary автоматически не удалять. Готово после A–C, публичных проверок и
инструкции восстановления; ручной блок вместо регистрации поддержанного клиента
не закрывает #1636. **7–10 дней**, без глобальных конфигов и остальных агентов.
Этот PR содержит только план.
