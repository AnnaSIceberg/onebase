# Связанный выбор параметров отчёта

Ссылочный параметр отчёта поддерживает `choice_filter` и `choice_label_suffix`:

```yaml
params:
  - name: Филиал
    type: reference:Филиалы
  - name: Направление
    type: reference:Направления
    choice_filter:
      - field: Филиал
        param: Филиал
    choice_label_suffix: Филиал
```

`field` — ссылочный реквизит справочника выбора; `param` — другой ссылочный
параметр отчёта того же типа. Несколько условий объединяются через И. Пустой
ведущий параметр означает все значения; пустой зависимый параметр остаётся
«все». При смене ведущего значения список обновляется, несовместимое выбранное
значение очищается. Сервер проверяет связь при формировании и экспорте: прямой
HTTP-запрос не позволяет передать несовместимую пару UUID. Проверка действует
также в REST `/api/v2/report/{name}` до выполнения запроса и компоновки JSON.

Порядок наследуется из `order_by` справочника, как при выборе в карточке.
`choice_label_suffix` добавляет представление связанного объекта в скобках:
`Ремонт (Москва)`. Хранимое представление справочника не меняется. Поиск,
постраничный подбор, первоначальные варианты и выбранное значение используют
одни серверные ограничения и подписи. Сохраняются права чтения и строковый
доступ пользователя. Метаданные условий никогда не принимаются от браузера.

Конфигурационный запрос отчёта по-прежнему определяет смысл пустых параметров:
например, `(&Филиал ЕСТЬ NULL ИЛИ Д.Филиал = &Филиал)`; настройка выбора не
добавляет отбор результата запроса автоматически.

Пустой родитель снимает только соответствующее условие `choice_filter`;
права чтения, строковый доступ, активность и исключение групп сохраняются.
Здесь нет дополнительных статических фильтров формы карточки: совпадение с
ней относится к `order_by`. Неизвестные поля, неверные типы, повторные условия,
более восьми условий и циклические зависимости блокируют `onebase check`
независимо от `--lint`.

Подбор параметра использует GET и статические пояснения справочника. Контекст
`choice_preview_proc` формы объекта не переносится в параметры отчёта: для
него нужен отдельный контракт источников, которого у параметра отчёта нет.

## Совместимость native B30

Контекстные ведущие параметры вычисляются сервером из настоящего отчёта; браузер не передаёт их значения. При недоступном actor/card выбор не расширяется. Внешний отчёт не получает configuration-only context. Обычные пустые параметры по-прежнему означают все значения.

Параметры поиска по истории сохраняют `choice_show_deleted` и отметку удаления. Этот ключ управляет списком выбора, а не запретом использования уже выбранной исторической ссылки. Enum-параметры, варианты запроса и доверенные bindings проверяются до исполнения, в том числе в экспорте и REST.
