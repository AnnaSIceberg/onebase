# Отборы по полям результата отчёта

Пользователь выбирает доступное поле результата, оператор и значение в панели
настроек. Тип определяется сервером из прямого пути к исходному полю и вхождения
источника с учётом текущих прав; имя выходного столбца само по себе ничего не
доказывает. Вариант с другим запросом получает собственную схему.

Условия объединяются через И. Числа сравниваются точно, даты — хронологически,
ссылки — по UUID, перечисления — по существующим значениям. Для пустых значений
есть отдельные операторы NULL. Скрытые поля и исходные подписи защищённой сущности
не предлагаются; сервер отвергает поддельный или устаревший отбор.

Отбор выполняется до лимита принятых строк, компоновки, итогов и пагинации API.
Экран, Excel, PDF и фоновый экспорт используют тот же план. Просмотр исходных
строк ограничен 100000 строками и 30 секундами; при превышении нет частичного
результата с неполными итогами. Личные варианты сохраняют условия и выбранный
вариант запроса. Явный выбор стандартного варианта сбрасывает личные настройки.

Пример `__settings` для формы или API:

```json
{"filters":[{"field":"Amount","op":"ge","value":"100.50"},{"field":"Day","op":"lt","value":"2026-11-18T00:00:00"}]}
```

Производные выражения, виртуальные таблицы и запросы с собственным FIRST,
неоднозначные колонки и неподтверждённый DSL не становятся доступными по alias.
Для `result_proc` с пользовательским отбором возвращается отказ до исполнения
модуля. Внутренние readonly effectiveFilters и guarded query executor проверяют
только входы; успешное выполнение этих helpers не доказывает происхождение
готового ТабДок и не разрешает его публикацию. Этот остаток зависит от host proof.

Политика ПДн — отдельная замороженная зависимость кандидата, не часть разрешения
на перенос этой ветки в интеграцию. Карточки и рабочие формы этим изменением
не переводятся в отчётную политику.
