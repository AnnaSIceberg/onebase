T8/П25 требует одну XLSX-книгу с отдельным листом на направление. Добавлен `КнигаТабличныхДокументов` / `SpreadsheetWorkbook`: `ДобавитьЛист(Имя, ТабДок)` сохраняет снимок, `Количество()` возвращает число листов, `Записать(Имя, "xlsx")` возвращает base64 одной книги для передачи вызывающим кодом.

**Stacked Draft, зависит от #2627.** Ветка содержит источник П1 и его test-only исправление закрытия XLSX. До принятия родителя эта зависимость видна в diff. Перед Ready требуется проверить самостоятельный diff относительно принятого родителя.

Листы записываются в один Excelize file общим писателем ТабДок: сохраняются числовые типы, оформление, объединения, размеры, печатные настройки, freeze, повтор шапки и группы. Добавление копирует состояние документа, поэтому повторное использование и очистка исходного ТабДок не меняют уже добавленный лист. Имена проверяются явно, включая UTF-8, длину, запрещённые символы и дубли без учёта регистра. Лимиты действуют на книгу целиком; ошибочное добавление не меняет книгу. Пустая книга возвращает ошибку. Три метода включены в справочник языка. Пример: `examples/tabular-workbook/README.md`.

Проверено: 49 целевых Go-проверок исходной ветки, сборка всех пакетов, i18ncheck и соответствие справочника. Независимое чтение openpyxl в обычном и потоковом режимах подтверждает два листа, числа 111/222 и красное/зелёное оформление после изменения исходного документа. В интеграционном Windows SDK B27r2 прошли 30 проверок через публичные CLI/HTTP/DSL, включая фактическую выгрузку книги. SDK — отдельный кандидат на базе B26; общие стенды не переключались.

CI остаётся обязательным: Linux/PostgreSQL/e2e/race прошли; Windows job сообщил сбой `TestTPColumnWidthsBrowserPlacementsAndEditors` на инициализации двух таблиц, причина проверяется. Полный зелёный CI пока не заявляется. Локальные PostgreSQL SKIP не считаются проверкой PostgreSQL. Draft сохраняется.
