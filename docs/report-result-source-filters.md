# Отборы входа result_proc

Пользовательские отборы `__settings.filters` (включая сохранённый пресет) применяются к полному результату запроса после RBAC/RLS и маскирования, до вызова `result_proc`. Модуль получает исходные типизированные значения выбранных строк. HTML, XLSX и PDF используют один замороженный результат модуля. Постоянные отборы доверенного YAML-варианта П2 остаются в SQL до лимита; пользовательский отбор не разрешает превысить `report_max_rows`.

Поддерживаются `eq/ne/gt/ge/lt/le/contains` и имена проекций без учёта регистра. Ссылочные UUID сравниваются по идентичности, `eq/ne`; поиск по представлению не добавляет чтение чужого справочника и явно отклоняется. Неизвестное поле/оператор, некорректный JSON или settings больше 64 KiB отклоняются; нефильтрованный результат вместо ошибочного отбора не публикуется. Для queryless result_proc непустой пользовательский отбор отклоняется HTTP 422: источник строится внутри модуля и платформа не может достоверно отфильтровать его вход.

REST v2 принимает те же явные `__settings.filters` и вариант. При непустом отборе читает полный разрешённый источник в существующем пределе REST 1000 строк, маскирует, фильтрует, затем применяет пагинацию/доверенную компоновку. Превышение этого предела даёт HTTP 422; бюджет не повышается и усечённый источник не выдаётся за полный. Без пользовательского отбора прежний REST-путь не меняется. REST возвращает строки/компоновку и не исполняет модуль result_proc.

Обычный UI-отчёт сохраняет прежнюю политику компоновки, предупреждения об усечении и разрешения представлений. Клиентская Composition не становится доверенным SQL или правами.
